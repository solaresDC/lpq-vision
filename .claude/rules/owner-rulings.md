## How the build runs (standing rules)
- A section arrives in parts, one part per message (Claude Code's input limit is about 50,000
  characters). Execute NOTHING until the last part, the one that ends with the deviations line.
- An exact edit quotes the current text it replaces. If it does not match: STOP that edit, apply the
  rest, run the checks, HOLD the commit and report the current text. A STOP is the right move, never a
  guess.
- Exact edits are applied with your Edit tool and whole files are written with your Write tool (a
  script passed through the shell mangled backslashes in the handover).
- Report every command's output (long build progress and per-request noise may be trimmed: say so).
  Any action outside the block is a deviation: list it in the deviations report.
- Shell: the listed commands run in Git Bash with MSYS_NO_PATHCONV=1 (running them from PowerShell is
  not a deviation). Always `-f compose.mac.yaml`. A bare sleep is blocked in your shell: use a timed
  loop and list it as a deviation. docker cp and docker exec with Windows paths work from Git Bash
  (with MSYS_NO_PATHCONV=1) and from PowerShell.
- Files: LF, a final newline, UTF-8 without BOM; check with `git ls-files --eol`. JavaScript syntax is
  checked with `node --check` on .mjs copies (node reads a .js file as CommonJS).
- Blocks never contain the dollar sign (the chat's renderer eats it): a new regex ends with \Z instead,
  a line that must keep one is copied from git, and every block scans its added lines with chr(36).
- Where files go: throwaway files (the .mjs copies, temporary output) in your session scratchpad; a
  file a later step reads again (a snapshot) in `claude-autogenerated-docs/scratch/`; a throwaway
  check script in `photos/_smoke/`, run inside the fastapi container. `claude-autogenerated-docs/`
  and `photos/` are git-ignored.
- Checks make their own test accounts (random passwords, never printed), test dishes and test sites,
  and delete them in a finally block; a check that writes config.yaml keeps its exact bytes and writes
  them back. A check scans its own output for the passwords it made and for the env secrets (the bot
  token, the chat id, the API key) and fails if one appears; Telegram senders are replaced by a stub
  that raises (or records, when the check tests a send); every SQL statement's placeholders are verified
  against the keys passed (an AST check). A check never touches the laptop's real cuarto row (born by
  set_password in 3.5).
- Smoke tests use photos/smoke_diet.jpg (the 1600 px light copy), never a full-size original (Fase 2
  HQ ruling 2.15).
- Commits: the section's exact title as the message, plus the same Co-Authored-By trailer the earlier
  commits carry. NEVER push: the owner pushes from PowerShell (Tailscale off for the push only).
- Laptop test edits to config.yaml and textos.yaml are reverted before each commit (CLAUDE.md rule 19).
- The laptop's bot stays STOPPED: one poller per token (the server's bot is the live one), and the
  repo's bot cannot run until 3.11 rewrites it. Never press Start on the whole project in Docker
  Desktop (it starts the bot too).
- If Docker Desktop is closed, you may open it yourself (the 3.2 and 3.10.2 precedent): it brings back
  only the containers that were running. Never press Start on the whole project, and confirm the bot
  is still stopped.
- The menu version never rewinds: a bump on a REAL dish is permanent on that database, so only a block
  bumps one. A check bumps only its own test dishes and deletes them at the end (MAX then returns to
  its value).
- `/log` saves the session log to claude-autogenerated-docs/sessions/. When a conversation runs out of
  space, a new one starts from this file, CLAUDE.md, the newest logs and git.

### 3.10.2 (owner, 7 and 8 Oct 2026): the Menú tab IS the recetario (built in Section 3.10.2)
- The recetario is no longer post-demo (amends SPEC section 3): the Menú tab is the recetario book, and
  the ficha reader is built now.
- The book: one page per dish with all its info, turned sideways (swipe on the phone; ◀ ▶ and the
  arrow keys on the computer); a "Página N de M" counter; an index with each dish's small photo.
  "Ordenar páginas" (admin) sets one order for the brand, the same in every site. A page is read-only
  until Editar.
- Leer ficha (admin): a photo of ONE page of the restaurant's recetario is read by the model (about 5
  to 15 s, about 1 to 2 US cents) and pre-fills a NEW page. Doubtful items (missing grams, ml) come
  marked; nothing is saved until the person saves; everything can be changed by hand. "Crear a mano"
  opens the same page empty.
- The clave (dish_id) is made by the system from the name: never typed, never shown, never changed. A
  rename keeps the clave and leaves a name history ("Antes se llamó").
- Components are written the way people say them, accents included; their internal keys are made by
  the system and never change (the model answers with the keys). Renaming a component never bumps the
  menu version; adding or removing one bumps it (global MAX+1, behind the double confirm).
- "Tipo de plato" stays hidden until the báscula exists and is switched on, and disappears when it is
  off. Stored values are kept.
- "Notas para el modelo": one per dish, read by the model with that dish from the next plate. The
  component descriptions that lived only as YAML comments in menu.yaml are copied once into each
  dish's notes (the laptop in 3.10.2, the server in 3.18), visible and editable on each page.
- Every photo in the mostrador opens in a viewer INSIDE the page (dark background; ✕, a click outside
  or Esc closes it; ◀ ▶ moves between that block's photos). Never a new tab.
- Managers read the book; only the admin edits pages, orders them and reads fichas (the SPEC: a
  manager never touches dish definitions). A manager still handles its own site's local photos.
- This file exists, and every section that changes a ruling or a promise updates it.
- Built defaults (HQ's standard choices; the owner may change any of them):
  - Notes: up to 1000 characters per dish. NULL = never written, '' = cleared by a person. A note never
    bumps the version; the model reads it as one line under the dish's components.
  - Order: a dish never placed goes last, by name; a new page goes last.
  - Names: a name equal to another dish's (on or off), ignoring case and accents, is refused. A dish may
    be called "Desconocido": its clave becomes platillo_desconocido ("desconocido" is the model's word
    for an unknown plate).
  - Leer ficha: a photo or screenshot of ONE page (no PDF); one call outside the queue (max_tokens
    2048); the photo is never stored; one menu.ficha bitácora row keeps its tokens.
  - menu_builder keeps listing the dishes by clave, so ordering the pages never changes what the model
    reads.
  - The one-time copy (scripts/notas_from_menu.py) writes notes only where they are NULL and labels
    only where a component has none, one line per described component ("Etiqueta: descripción.", the
    accents restored). It never touches keys, portions or versions.

### 3.9.1 to 3.9.6 (owner): accounts and passwords
- Accounts CAN be deleted (amends SPEC section 3). Every account has a permanent number (users.uid,
  never reused) written in the bitácora next to the name. Eliminar: type the exact name, then a final
  "permanent" confirm. The account closes at once into "Eliminadas", recoverable for 30 days, its name
  reserved meanwhile; 5 days before the erase the admin chat is warned (text cuenta_por_borrarse, sent
  by the bot from 3.11); day 30 erases it. Never yourself, never the last active admin, never cuarto.
- Your own row and the only active admin never show Desactivar or Eliminar (chip "único admin activo").
- Nobody ever sees a password (hash only). The admin changes one through a window: the new password
  twice with one "ver" for both, then "¿Seguro…?", and that account's sessions close. Copy and paste
  are blocked in password fields.
- Cuentas shows when and by whom each password changed, the last 5 changes, the full history (100) and
  a per-row history. Managers change their own in the "Mi contraseña" card; the admin, from the rows.
- Accepted limit: a password set with set_password over ssh shows "set_password" in Cuentas'
  Contraseña column and is missing from the password history lists (its bitácora row is the system
  row users.set_password).
