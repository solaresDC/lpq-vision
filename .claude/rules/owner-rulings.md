## How the build runs (standing rules)
- A section arrives in parts, one part per message (Claude Code's input limit is about 50,000
  characters). Execute NOTHING until the last part, the one that ends with the deviations line.
- An exact edit quotes the current text it replaces. If it does not match: STOP that edit, apply the
  rest, run the checks, HOLD the commit and report the current text. A STOP is the right move, never a
  guess.
- Exact edits are applied with your Edit tool and whole files are written with your Write tool (a
  script passed through the shell mangled backslashes in the handover).
- Report every command's output (long build progress and per-request noise may be trimmed: say so).
  Any action outside the block is a deviation: list it in the deviations report.
- Shell: the listed commands run in Git Bash with MSYS_NO_PATHCONV=1 (running them from PowerShell is
  not a deviation). Always `-f compose.mac.yaml`. A bare sleep is blocked in your shell: use a timed
  loop and list it as a deviation. docker cp and docker exec with Windows paths work from Git Bash
  (with MSYS_NO_PATHCONV=1) and from PowerShell.
- Files: LF, a final newline, UTF-8 without BOM; check with `git ls-files --eol`. JavaScript syntax is
  checked with `node --check` on .mjs copies (node reads a .js file as CommonJS).
- Blocks never contain the dollar sign (the chat's renderer eats it): a new regex ends with \Z instead,
  a line that must keep one is copied from git, and every block scans its added lines with chr(36).
- Blocks carry no backslash-u escape and no decomposed character (3.13.1's lesson): your tool calls turn
  a backslash-u escape into the character itself, and your Edit tool composes characters (NFC) before
  matching. Code that needs such a character builds it with chr().
- Where files go: throwaway files (the .mjs copies, temporary output) in your session scratchpad; a
  file a later step reads again (a snapshot) in `claude-autogenerated-docs/scratch/`; a throwaway
  check script in `photos/_smoke/`, run inside the fastapi container. `claude-autogenerated-docs/`
  and `photos/` are git-ignored.
- Checks make their own test accounts (random passwords, never printed), test dishes and test sites,
  and delete them in a finally block; a check that writes config.yaml keeps its exact bytes and writes
  them back. A check scans its own output for the passwords it made and for the env secrets (the bot
  token, the chat id, the API key) and fails if one appears; Telegram senders are replaced by a stub
  that raises (or records, when the check tests a send); every SQL statement's placeholders are verified
  against the keys passed (an AST check). A check never touches the laptop's real cuarto row (born by
  set_password in 3.5).
- Smoke tests use photos/smoke_diet.jpg (the 1600 px light copy), never a full-size original (Fase 2
  HQ ruling 2.15).
- Commits: the section's exact title as the message, plus the same Co-Authored-By trailer the earlier
  commits carry. NEVER push: the owner pushes from PowerShell (Tailscale off for the push only).
- Laptop test edits to config.yaml and textos.yaml are reverted before each commit (CLAUDE.md rule 19).
- The laptop's bot stays STOPPED: one poller per token (the server's bot is the live one). A live bot
  test on the laptop sits between a listed stop of the server's bot and its start again (the owner
  runs both in the section's ✋). Never press Start on the whole project in Docker Desktop (it starts
  the bot too).
- If Docker Desktop is closed, you may open it yourself (the 3.2 and 3.10.2 precedent): it brings back
  only the containers that were running. Never press Start on the whole project, and confirm the bot
  is still stopped.
- The menu version never rewinds: a bump on a REAL dish is permanent on that database, so only a block
  bumps one. A check bumps only its own test dishes and deletes them at the end (MAX then returns to
  its value).
- `/log` saves the session log to claude-autogenerated-docs/sessions/. When a conversation runs out of
  space, a new one starts from this file, CLAUDE.md, the newest logs and git.

### 3.13.1 (owner, 11 and 12 Oct 2026; built in Section 3.13.1): one-day hours, Sitios y cuentas live
- The bot changes a day's hours from Telegram: only today or tomorrow, and only for that day. /hoy and
  /manana show that day; /abrir [hoy|mañana] HH:MM, /cerrar [hoy|mañana] HH:MM, /cerrar ya,
  /hoy HH:MM HH:MM, /manana HH:MM HH:MM, /hoy cerrado and /manana cerrado change it. No day = today.
  Every answer names the day ("🟡 demo: hoy (domingo 11) se cambió la apertura a las 10:00. Mañana
  vuelve el horario normal."), and every change is that 🟡 in the group plus a bitácora row. The
  regular hours change only in the mostrador. /extender stays.
- Sitios y cuentas follows the system by itself every 5 s: a relevo made from /captura or from another
  window shows up without reloading.
- Built defaults (HQ's standard choices; the owner may change any of them):
  - /mañana with the ñ works too (Telegram ends a command's name at the ñ, so the bot reads the text
    itself); written to another bot (/mañana@OtroBot) it is ignored, like any command.
  - Each change is ONE row of horario_extensiones holding the whole new state of that service day
    (dia, abre_at, until = its close, cerrado); the latest row of a day wins; rows from before 3.13.1
    (no dia) are ignored. /extender writes the same kind of row. The bot writes that row and its
    bitácora row (horario.cambio: usuario "telegram: <the Telegram name>", detail {sitio, dia,
    comando, abre, cierra, cerrado}, never the chat id) in one transaction (hard rule 15; CLAUDE.md's
    Bot row).
  - "hoy": past midnight, a night still open is still hoy (the midnight law); otherwise the calendar
    day in the site's timezone. A close HH:MM is its first occurrence after that day's opening (after
    midnight = the next morning; in the hour that repeats when daylight saving ends, the coming one).
    The hours math runs in real time: "+2h" is two real hours on the nights the clock changes.
  - Refused, with the reason and the command that does it instead: a close already past (while open:
    /cerrar ya); moving the opening of a day open right now to an hour already past (/cerrar changes
    only the close); an opening before the previous day closes; a close at or after the next day's
    opening; closing all day a day already over; a change that changes nothing. Past midnight inside
    last night, every refusal also shows the mañana form.
  - /extender lengthens the night open now; otherwise today once its opening has come (even after an
    early close); before today opens, the nearer of last night and today (a day closed all day counts
    with its regular opening, and is refused). Never tomorrow (its answer says "hoy").
  - The worker's sweep removes a day's rows together, once all of them closed more than a day ago (the
    latest row alone would bring an older state back); the bot reads whole days, from the day before
    yesterday on.
  - Sitios y cuentas rebuilds in place a card whose data changed, never under someone's hands: it
    waits, with a note, while a window is open, the cursor is in one of its fields, a value was typed
    or chosen and not saved, a button is still working, or a gafete is on screen (the gafete gained
    "ocultar"). A site added or removed elsewhere rebuilds the whole tab on the same terms. The re-read
    never opens the login, and it stops when the tab is left or hidden.

### 3.13 (built in Section 3.13): the wall and the capture lane
- The gafete is ENFORCED (SPEC 1.3's matrix, and 3.13's promise list). Built defaults (HQ's standard
  choices; the owner may change any of them):
  - Writes (upload_burst, the frame push): THAT site's gafete only; a session alone is not a gafete
    (401).
  - Reads (the frame, the state, /api/upload): a session of the site (the admin's opens every site)
    or that site's gafete. A session of another site never shadows a valid gafete. Refusals: nothing
    presented 401; a gafete that is not this site's 403; another site's session alone 403. Since
    3.13.2 the gafete rides only the header (a machine's), and a phone camera takes its phone's pass.
  - /api/plates/{id}: a caller with no credential the api knows gets 401 (403 for a gafete no active
    site owns) whether or not the id exists; a known caller outside the plate's site gets the same
    404 as a missing id. /api/health stays free. No response shape changed.
  - A malformed request still gets its 400 first, then the wall, then the unknown site or camera. A
    name that cannot be a site (the slug pattern) is refused like a wrong gafete and never reaches
    the database.
  - Curl smokes carry -H "X-Device-Key: REPLACE_WITH_DEVICE_KEY" (the human copies the value from
    the mostrador).
- The measurements: every pushed copy gets its sharpness AND its luma (mean brightness, 0 to 255)
  from the same 640 px gray copy.
  - A camera's black streak starts at its first copy under the site's alerts.black_luma_max,
    survives a pause of up to 3 pushes (3 times capture.frame_poll_s) and ends with a brighter copy.
    The state shows luma, black_for_s (counted to the last copy; absent when not black) and up_s
    (the api's own uptime).
  - A burst whose EVERY readable frame sits under the site's floor is refused (400 with black: true):
    never stored, never billed. In a mixed burst only the frames above the floor compete (a black
    frame's noise can read sharp). /captura counts the refusal as discarded ("descartado: imagen
    negra"), never as an error.
  - Every decode is guarded: JPEG or PNG only, sized from the file's own header first, at most
    50 MP (a 48 MP phone photo fits). Anything else, bigger or broken is "not an image": the push
    and the burst answer 400, /api/upload stores it as it came. Never a 500, never a memory spike
    in the one process.
- Per-site knobs: the state, the push reply and upload_burst's frame cap read the site's own
  capture.diff_threshold, capture.settle_frames and capture.burst_frames; the state's sharpness_min
  and video_align.default_s are the site's too. capture.frame_poll_s stays global.
- The plate's ONE light file (ruling 3.10.1): the sharpest frame, and the curl road's photo, shrunk
  to 1568 on the long side (the reference photos' light-copy math: INTER_AREA, JPEG 85). A photo
  already that small, or bytes that are not an image, are stored exactly as they came. The file is
  named by its stored bytes, so a repeated burst stays a duplicate. upload_burst's reply carries
  shrink_ms (only when it shrank), and its log line both sizes. About 20 ms for a 1920x1080 frame on
  HQ's test machine; 21.9 ms on the laptop (3.13's report: 49,160 to 32,387 bytes).
- The align bitácora: align.start {site, camera, seconds, capped when capped}, written before the
  rope starts (a rope that cannot leave its row never starts); align.stop {site, camera,
  was_active}, after the stop (a stop for a camera the site does not have still answers 200 and
  leaves no row). The bot does not announce them (it announces the pause from the state).
- The calibration goes through the one writer (routes.py's private writer is gone): kitchen_edge is
  written quoted ("left"), and its bitácora row "calibration" carries despues, plus antes when
  there was one.
- Descartar on the server: POST /api/review/{id}/discard and the bulk action "discard" (before, a
  bulk discard fell into pendientes). Outside the session's site, unknown or already discarded = 404;
  reopen never pulls a row out of the papelera. A discard leaves a log line like the other review
  actions, not a bitácora row (the bitácora keeps the papelera's purge and eliminar-ya, 3.14). The
  review page's button is 3.14.
- The confianza count: /api/stats gains confianza {bajo_umbral, minima}: analyzed return rows ranked
  under EACH site's own confianza_minima, the papelera excluded; minima is absent when the sites in
  view differ. The panel's tile is 3.14.

  - Names: a name equal to another dish's (on or off), ignoring case and accents, is refused. A dish may
    be called "Desconocido": its clave becomes platillo_desconocido ("desconocido" is the model's word
    for an unknown plate).

  - menu_builder keeps listing the dishes by clave, so ordering the pages never changes what the model
    reads.
  - The one-time copy (scripts/notas_from_menu.py) writes notes only where they are NULL and labels
    only where a component has none, one line per described component ("Etiqueta: descripción.", the
    accents restored). It never touches keys, portions or versions.
